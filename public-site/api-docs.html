Reseller API

Sell Crapplet VPS, hosting and servers on your own website under your own brand. Your site calls this API; orders are paid from your Crapplet wallet at your wholesale price; we set the service up and tell your site when it's ready.

Base URL  https://crapplet.co.in/api/v1/reseller

Everything is JSON over HTTPS. Your customers never see Crapplet — they buy from you, and you manage their services through this API or your reseller dashboard.

Before you start: you need an approved reseller account (apply in the client area under Reseller) and money in your wallet (client area → Wallet & credit → Add funds).

Quick start

  1. Open your reseller dashboard → API tab → Create API key. Copy the key (it starts with ck_) — it's shown once.
  2. List the plans you can sell and their wholesale prices: 
    curl -H "Authorization: Bearer ck_YOUR_KEY" \
  https://crapplet.co.in/api/v1/reseller/plans
  3. Place an order when your customer pays you: 
    curl -X POST -H "Authorization: Bearer ck_YOUR_KEY" -H "Content-Type: application/json" \
  -d '{"planId":"PLAN_ID","cycle":"MONTHLY","hostname":"vps1.customer.com","osTemplateId":"OS_ID","reference":"ORDER-1001"}' \
  https://crapplet.co.in/api/v1/reseller/orders
  4. Set a webhook to hear when the server is ready, or poll GET /services/{id} until status is ACTIVE, then give your customer the IP and login.

Authentication

Send your API key as a Bearer token on every request:

Authorization: Bearer ck_ab12cd34_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
  • Keys are created and revoked in your reseller dashboard. A key only ever sees your customers, services and invoices.
  • Keep keys on your server. Never put a key in browser JavaScript or a mobile app — anyone could read it.
  • When creating a key you can limit it to your web server's IP addresses; requests from anywhere else are refused.
  • A missing, wrong or revoked key gets 401.

Amounts, errors and limits

Money

All amounts are integers in paise (₹1 = 100). 45000 means ₹450.00. Prices are before GST; invoices show the GST added.

Billing cycles

MONTHLY, QUARTERLY, SEMIANNUAL, ANNUAL, BIENNIAL, TRIENNIAL — only the cycles a plan lists in prices can be ordered.

Errors

Errors return a non-2xx status and a JSON body:

{ "error": "Plan not found — list plans with GET /plans", "code": "NOT_FOUND" }
StatusMeaning
400Invalid request. Validation errors include details with the field problems.
401No key, a wrong key, or a revoked key.
402INSUFFICIENT_FUNDS — your wallet can't cover it. Top up, then pay the invoice.
403Your reseller account isn't approved (or is suspended).
404Not found — or not yours.
409Conflict, e.g. that domain already has a hosting account.
429RATE_LIMITED — more than 300 requests a minute on one key. Wait for the time in the RateLimit-Reset header.
5xxOur side. Safe to retry orders when you send a reference (see below).

Selling on your website — the full flow

  1. Show plans. Call GET /plans (cache it for a few minutes). Show your price — wholesale is what you pay us.
  2. Customer pays you on your website, with your own payment gateway.
  3. Order from us with POST /orders, passing your own order number as reference. If your request times out, send it again with the same reference — you'll get the same order back, never a second one.
  4. Wait for setup. The service goes PROVISIONING → ACTIVE (usually 1–5 minutes for a VPS). The service.active webhook tells you; or poll GET /services/{id}.
  5. Hand over. GET /services/{id} returns the IP, username and password. Email them to your customer.
  6. Renewals. Before each due date we create a renewal invoice for you. It's paid from your wallet automatically when the balance covers it — keep your wallet topped up. If not, pay it with POST /invoices/{id}/pay. Unpaid renewals are suspended and later terminated, as for any customer.

Orders

POST/orders

Order any plan. Paid from your wallet; the service is set up as soon as it's paid.

FieldTypeDescription
planIdrequiredstringFrom GET /plans.
cyclestringDefault MONTHLY.
hostnamestringVPS hostname, e.g. vps1.customer.com. Required for VPS.
domainstringThe website domain for hosting plans, e.g. customer.com. Required for hosting.
osTemplateIdstringOperating system from the plan's os list. Required for VPS.
serverIdstringLocation from the plan's locations (optional).
ipIdstringA specific IP from GET /ips — only for plans with allowIpSelection.
customerIdstringYour end customer from POST /customers (optional, for your records).
retailAmountintegerWhat you charge your customer, in paise (optional, for your reports).
referencestringYour own order number. Strongly recommended: repeating a request with the same reference returns the original order instead of creating another. The Idempotency-Key header works the same way.

Webhooks

Instead of polling, give us a URL and we POST a signed JSON event to it whenever something changes.

EventWhen
service.activeA new service is ready (IP and login are in GET /services/{id}).
service.failedSetup failed. Our team is alerted and will retry or refund.
service.suspendedSuspended — by you, by us, or for an overdue renewal (suspendReason).
service.unsuspendedRunning again.
service.terminatedTerminated; the server is gone (terminationReason).
service.reinstalledReinstall finished — fetch the new password.
invoice.paidAn order, renewal or top-up invoice was paid.

Verify every request

Compute HMAC-SHA256 of timestamp + "." + raw body with your signing secret and compare it to the header. Reject requests older than 5 minutes.

<?php
$secret = getenv('CRAPPLET_WEBHOOK_SECRET');            // whsec_…
$body   = file_get_contents('php://input');              // the raw body, before json_decode
$ts     = $_SERVER['HTTP_X_CRAPPLET_TIMESTAMP'] ?? '';
$sig    = $_SERVER['HTTP_X_CRAPPLET_SIGNATURE'] ?? '';
$expect = 'sha256=' . hash_hmac('sha256', $ts . '.' . $body, $secret);
if (!hash_equals($expect, $sig) || abs(time() - (int)$ts) > 300) { http_response_code(400); exit; }

$event = json_decode($body, true);
// ignore events you've already processed: store $event['id']
if ($event['event'] === 'service.active') {
  // look up your order by $event['data']['reference'], then fetch login details:
  // GET /services/{$event['data']['id']} → email IP + password to your customer
}
http_response_code(200);
import crypto from "node:crypto";
import express from "express";
const app = express();
app.post("/crapplet-webhook", express.raw({ type: "application/json" }), (req, res) => {
  const ts = req.get("X-Crapplet-Timestamp") ?? "";
  const expect = "sha256=" + crypto.createHmac("sha256", process.env.CRAPPLET_WEBHOOK_SECRET).update(`${ts}.${req.body}`).digest("hex");
  const sig = req.get("X-Crapplet-Signature") ?? "";
  const fresh = Math.abs(Date.now() / 1000 - Number(ts)) < 300;
  if (!fresh || sig.length !== expect.length || !crypto.timingSafeEqual(Buffer.from(sig), Buffer.from(expect))) return res.sendStatus(400);
  const event = JSON.parse(req.body.toString());
  // dedupe on event.id, then handle event.event
  res.sendStatus(200);
});

Delivery

  • Reply with any 2xx within 10 seconds. Do slow work after replying.
  • If we don't get a 2xx, we retry twice: after 10 seconds and after a minute. Your dashboard shows the last delivery result.
  • An event can arrive more than once — use id to ignore repeats. Webhooks are a signal; GET /services/{id} is always the truth.
  • The URL must be public https://.
PUT/webhook

Set or change your URL (you can also do this in the dashboard). The response contains a new signing secret, shown once.

{ "url": "https://yourwebsite.com/crapplet-webhook" }
→ { "url": "https://yourwebsite.com/crapplet-webhook", "secret": "whsec_…", "note": "Store this secret now…" }

GET /webhook shows the URL and the last delivery · POST /webhook/test sends a test service.active event (with "test": true) and returns the result · DELETE /webhook stops events.
